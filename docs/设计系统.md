# 设计系统

> 活文档。`shared/tokens.css` 是唯一定义处，`tools/build.js` 构建时把它内联到每个插件 `styles.css` 的最前面；插件样式只消费 `var(--os-*)`。

这次是真的唯一。6.0 之前 `design/00-tokens.css` 也写着「唯一真相源，禁止再写具体色值」，但它被零个文件引用，副本躺在 `.obsidian/snippets/` 而 `appearance.json` 的 `enabledCssSnippets` 是空的——从未启用。声明唯一没有用，得有机制。现在的机制是构建内联加 `tools/check.js` 的色值提示。

## 对比度闸门

`tools/contrast.js` 对两套主题逐条校验 20 项关系，不达标直接构建失败。这类判断眼睛不可靠——起草 6.1 方案时，我两次凭截图判断颜色都判错了（深色主按钮、任务标题），像素采样才给出正确答案。

| 关系 | 下限 | 挡住的是 |
| --- | --- | --- |
| ~~卡片 / 页面底~~ | ~~1.25~~ | 6.5 并进上面那条二选一 |
| 次级面 / 页面底 | 1.12 | 6.0 时是 1.09 |
| 分隔线 / 卡片 | 1.80 | 6.0 时是 1.43，而所有分区都靠这条线 |
| 正文、次要文字、强调色、危险色对各自底色 | 4.50 | 次要文字铺在 soft 卡片上曾是 4.18，低于 AA |
| 第二强调色 / 卡片 | 4.50 | 6.5 新增。它既当字也当按钮底，两个用途量的是同一对关系 |
| 卡片可辨（面 **或** 线） | 1.25 / 1.80 | 二选一。6.0 是两条都不够，才该被拦 |

6.1 只动明度、不动色相：页面底 `#f4eee5 → #e8e1d7`，次级面 `#eee4d7 → #dcd4c6`，分隔线 `#ded2c3 → #c6b9a8`，次要文字 `#7d685b → #6a5749`。文字的颜色一直是对的，塌掉的是面与面之间的明度差。

## 6.5 换色：纸白 + 深绿

6.1 只动明度、不动色相，因为当时塌掉的是面与面的明度差。6.5 动的是色相：整套暖纸底偏黄，而层级一直只靠「更淡」表达，淡到一定程度就只剩浑浊。

| | 6.4 | 6.5 |
| --- | --- | --- |
| 卡片 | `#fffaf3` 奶油 | `#FFFFFF` 纯白 |
| 页面底 | `#e8e1d7` | `#F8F6F1` 暖燕麦 |
| 次级面 | `#dcd4c6`（交互卡的底） | `#EAE6DC`（只剩悬浮态） |
| 分隔线 | `#c6b9a8` 暖棕 | `#C9C0AA` 一条线管所有 |
| 正文 | `#3d3029` | `#25201D` 暖焦糖黑 |
| 次要文字 | `#6a5749` 浑暖灰 | `#2D4739` 复古墨绿 |

三个判断值得记下来：

**次级面改成比页面底亮。** 闸门要的是「`--os-bg` 和 `--os-soft` 分得开」，没规定方向。旧值比页面底暗，于是「今日要务」那张卡是全页最黄的一块——它是交互卡，却长得像一块底。改成往白走，1.16 照样过闸，而卡片全体归白。

**层级从明度换成色相。** 旧的次要文字 `#6a5749` 和正文只差明度、不差性质，所以「次要」只能靠更淡表达。换成一个不同色相的深绿之后，明度可以留得很深——它对白卡 9.73，比旧值还高，却明显不是正文。

**赤陶红收窄到两处**：左上角的 L，和专注卡里那一个「开始专注」。其余原本用强调色的地方（主按钮、状态标签、高优先、分段选中态、今日要务标记）全部走新增的 `--os-accent-2`。一页里只有一个地方是红的，那个地方才叫重点。

### 闸门拦了两次，第二次它自己的措辞是错的

**第一次**：方案给的页面底是 `#F7F3EA` 配纯白卡，量出来 **1.11**——正好是 6.0 那个数。解法是保住色相与饱和度、只压明度，得到当时的 `#EDE4D0`。

**第二次**：下一轮细则说「提亮净化底层」，给了 `#F8F6F1`；同时把卡片描边定成 `#E6E2D8`。量出来面差 1.08、描边 1.29——两样都撑不住，卡片和底之间什么都没有。

但这一次暴露的是**规则本身写窄了**。原规则写的是「面与面要有明度差」，而真实要求是「卡片要能被认出来」——白卡配一条看得清的描边同样成立，那是另一种正当做法。所以这条改成二选一：

```js
{ any: [{ a: "--os-paper", b: "--os-bg", min: 1.25 },
        { a: "--os-line",  b: "--os-paper", min: 1.8 }], ... }
```

放宽之后 6.0 那次欠账仍然拦得住——它是面 1.11 **且** 线 1.43，两条都不够。测试里把这一点钉死了：不只断言「不合格」，还断言两条候选各自的实测值，否则将来有人把其中一条下限调到 0，那个测试照样绿。

于是页面底可以真的用 `#F8F6F1`，代价是描边从 `#E6E2D8` 压到 `#C9C0AA`（1.81）——仍然是 1px 的细线，但不再是隐形的。分区总得有人扛。

顺带一个反直觉的量化结果：`#EDE4D0` 和 `#F8F6F1` 的**明度只差 8 个点**（87.3% vs 95.9%），饱和度差 12 个点（45% vs 33%）。「发闷」来自饱和度，不是来自暗。

深色那套同理：`#171A17` 的墨绿底配 `#2A2E29` 的卡，1.27；次要文字用浅鼠尾草绿 `#A9BBA5`。两套是同一个判断的两个方向，不是两套独立配色。

## 6.6 液态玻璃

面板改成半透明白底加 `backdrop-filter: blur(20px) saturate(130%)`。四条边不是一个颜色——上缘和左缘受光（`rgba(255,255,255,.85)`），下缘和右缘背光（`rgba(130,115,95,.12)`）——这一条比模糊本身更决定它像不像一块有厚度的玻璃：模糊只让背后糊掉，是那圈方向性的高光让它有了朝向。

### 磨砂需要背后有东西

`backdrop-filter: blur()` 模糊的是面板**背后**的东西。整页底原来是一块平色，模糊一块平色还是同一块平色——整套玻璃写下去，屏幕上一点变化都没有。

所以页面底加了两道极淡的径向渐变（左上鼠尾草、右上暖赤陶）。它们不是装饰，是这套材质唯一的输入。改配色时如果把这两道去掉，玻璃会安静地退化成半透明白块，而且不会有任何报错。

### 番茄钟的加强玻璃

番茄钟面积最大，普通玻璃在这块尺寸上很容易重新读成白色实心卡；而且旧规则 `.os-focus { background: var(--os-focus) }` 会直接盖掉通用面板的玻璃底。6.8 起它单独使用 `--os-focus-glass`、`--os-focus-sheen` 与 `--os-focus-blur`：底色浓度更低，模糊固定为 28px，饱和折射为 165%，再叠一层左上受光与右下暖色反射。浅色和深色主题分别定义，不再依赖当前为 `none` 的通用 `--os-glass-blur`。

### 玻璃令牌不进闸门

`--os-glass` 那几个是 rgba，`tools/contrast.js` 只认字面十六进制，所以它们量不了。文字实际压在什么底上由 `--os-paper` 记录：那是玻璃叠在页面底上算出来的等效色（白 0.68 叠 `#F8F6F1` 得 `#FDFCFA`）。

**两者必须同步改。** 只改 `--os-glass` 不改 `--os-paper`，闸门量的就是一块界面上并不存在的颜色——它会继续报「全部达标」，而那个结论跟屏幕上的东西没有关系。

### 表盘尺寸跟高度走

专注台的进度环第一版按容器**宽度**定尺寸（`min(62cqw, 232px)`），在真实窗口里把大漆按钮挤出了卡片下沿。夹具一条都没响——面板体自带 `overflow-y:auto`，内容超了它就安静地滚，溢出断言量不到。

改成跟容器高度走。上限 200px 是量出来的：面板体 394px，模式条 / 绑定条 / 珠子 / 按钮组占掉 192px。凡是「一列固定元素加一个可伸缩元素」的卡片，那个可伸缩的都该按高度定，不按宽度。

## 7.0 任何背景下都要认得出字

6.7 把 Windows 聚焦壁纸挂上页面底之后，这套设计系统的一个隐含前提没了：**它是按一个固定的底设计的**，而壁纸是每天换的不受控输入。实拍截图取样 14 处文字，7 处低于 AA 4.5、5 处低于 3.0。

### 规律不是「哪几处坏了」，是余量

| 文字 | 对白卡的余量 | 壁纸上实测 |
| --- | --- | --- |
| `--os-ink` | 13 以上 | 6.0 – 9.2，全过 |
| `--os-muted` | 6.5 定的是「刚好 4.5」 | 2.43 – 3.35，全塌 |

分界线不是「在不在卡里」。**固定的底上 4.5 是合格线，不受控的底上 4.5 是必然失守**——它没有任何浮动空间。6.5 那次把 `--os-muted` 从 `#7C756E` 压到 `#6C6660`，理由是「保色相压暗到刚好过 4.5」，那个判断在当时成立，在壁纸进来之后不成立。7.0 压到 7.0 以上。

### 模糊一片亮天空之后还是一片亮天空

`--os-glass-blur` 在 6.6.1 被设成 `none`，注释里写着「将来页面底换成有细节的东西，模糊就重新有意义了，那时改这一个令牌即可」。壁纸 6.7 就到了，没人回来翻。7.0 翻回来了，但**不是单纯的 blur**：

模糊削掉的是高频细节，平均亮度一点没变，而对比度输在平均亮度上。所以后面跟着钳位——`contrast()` 把任意背景往中灰压，`brightness()` 再整体抬起来，于是不管背后是雪山、深海还是纯黑，透到面板上的那一层都落进一条已知的窄带。

**钳位只在背后真有照片时生效。** 第一版无条件开，结果把 `--os-bg` 那块暖燕麦也拖向中灰，页头天气卡变成一个灰方块。开关是 `body.os-wallpaper-on`，由 l-os-widgets 和 `--os-wallpaper` 同进同出地挂（见[架构与边界](架构与边界.md)）。类不在时两个令牌各自退回 6.8 的值，样式表里没有任何分支。

### 遮罩拆成两层

| 层 | 令牌 | 谁说了算 |
| --- | --- | --- |
| 画面层 | `--os-scrim` | 用户那个「图片可见度」滑块，可以一路滑到 0 |
| 托底层 | `--os-scrim-floor` | 闸门，滑块碰不到 |

拆分的理由：**照片要的位置和文字要的位置不是同一块**。页边、留白、水槽那些地方照片可以完全清晰，而且那正是它最好看的地方；压着字的地方不行。它们原来共用一个滑块，所以只能二选一。

在这之前，可读性是一个用户能滑到零的设置项——`wallpaperVisibility` 滑到 100 时 `--os-scrim-opacity` 就是 0——而且这件事对两道旧闸门都不可见，因为它是运行时状态，不是令牌。

### 没有面的文字，最低走 `--os-body`

页标题、页副标题、页头元信息、页脚：这四处不在任何面板里。它们靠页头和页脚各一道渐变托底带——不是盒子，是一道看不出边界的暗化。

规则写死：**没有面的文字不许用 `--os-muted`。**「次要」那一级的余量是为有面的地方留的。

这条是闸门逼出来的：修完页头之后把锚点表加宽，当场量到页脚 **1.07**。同一个病，只是此前没人看它。

### 闸门：`tools/legibility.cjs`

前三道闸门管令牌和构图，管不到「一张没见过的照片」。这一道不量令牌，量**渲染结果**：把真正挂载的界面摆在八种最坏背景上（纯白、纯黑、高饱和红蓝、亮天空、雪山高光、明暗对半，以及「没挂壁纸」那条路径），在 11 个文字锚点处把字设成 `transparent` 再截那一小块，拿到的就是它真正压着的合成底色。

这同时解掉了一笔旧账。设计系统此前写着「`--os-paper` 是玻璃叠在页面底上**算出来**的等效色，两者必须同步改，不然闸门量的是一块界面上并不存在的颜色」——那是把正确性寄托在人记得同步上。**需要人记得的机制不是机制。** 现在那个值是量出来的。

闸门自带一条防空转断言：量到的锚点数少于下限直接报错。否则选择器一改名，它会一声不响地什么都不量，然后报「全部达标」。

跑法：`node tools/legibility.cjs` 独立跑（用代表性结构，图快），或跟着 `node tools/smoke-visual.cjs` 跑在真界面上（那一趟才是闸门）。

### 课程色：实色，不是玻璃

课表的课块是全系统唯一一处「大面积、带颜色、上面压着小字」的东西。它们用实色底，不用 rgba：课块压在玻璃上，玻璃背后是每天换的壁纸，半透明的课块会把照片透上来，字的对比度就又成了照片的函数。实色之后，块上的字对块的对比度就是令牌里那个数，`contrast.js` 量得到、量得准。

- 字对底下限取 **7**，不是 4.5：块里是 11–12px 的小字，而整页挂在壁纸上，按 7.0 那条「留余量」的规矩。实际取值都在 8.3 以上。
- 左缘色条按图形的 3.0 量（对卡面），实际 3.8 以上。深色下课块和卡面差得不多，那道色条是区分课程的主要线索。
- 六组色相取 iOS 系统色那六个（绿、橙、蓝、黄、紫、青），压成淡底加深字。第一版（换 iOS 之前）取的是能和暖燕麦底相处的低饱和色：鼠尾草、赤陶、石板蓝、赭石、梅紫、青灰。按课程代码的字典序分配，改表格行序不换颜色。
- 课块、今日行、色标、「下一节」卡都只读三个局部变量 `--c-bg / --c-ink / --c-edge`，由 `.is-c1…6` 一次性落好。
- 此刻线用强调色。
- 上完的课退成 `--os-muted`，不用透明度：透明度会把壁纸透上来。

`legibility.cjs` 给课表页另有一张锚点表 `SCHEDULE_ANCHORS`（课块标题、课块时间、刻度、星期、今天日期、下一节时间……），在八种最坏背景上量。时间刻度第一版用 `--os-muted`，纯黑背景上量到 4.88，换成 `--os-body`。

大数字和标题走 `--os-display`：专注计时、左栏时钟、页头与左栏气温、课表的日期与「下一节」时间、统计读数、页标题。它原名 `--os-serif`，6.5 起是 Bodoni 一路的高反差衬线；7.0 换成 Segoe UI Variable Display，大数字用 300 细字重（iOS 锁屏时钟与计时器的做法），名字随之改掉——一个叫 serif 的令牌里装着无衬线，下一个人一定会被骗一次。

只用系统字体：部署白名单只有 `main.js`、`manifest.json`、`styles.css` 三个文件，字体文件带不进插件目录。Segoe UI Variable 是 Windows 11 自带的可变无衬线，和 SF Pro 同一类；取不到退回 Segoe UI，中文走微软雅黑 UI。

字阶只有四级加一个计时器专用展示号。5.4.0 之前散落 22 种字号，差 1px 的相邻值到处都是——密度上去了但层次没建立。工作台在 `@container` 查询里按尺寸重定义这几个字号，改的是 `.os-root`，只影响工作台视图内部，不回头影响别的插件。

WWDC 2026 公布的 iOS 27 / macOS 27 对液态玻璃做了几处改动，这里逐条对应：

| 统一磨砂顶栏 | `.os-header` 是一整条玻璃，用负边距贴满 main 的上左右，替掉原来那道渐变托底带；它带钳位，页标题压着的底有下限 |
| 全局统一圆角 | 只留三个值：卡片 24、卡内块 14、控件胶囊 |
| 侧栏贴窗口边，只有当前项的图标带颜色 | 左栏不留缝，右边一道暗边；选中项一层填充 + 加粗，只有它的图标是系统蓝 |
| 适配「减少透明度」 | `prefers-reduced-transparency` 下玻璃换成实色面 |

配色从暖燕麦 + 墨绿 + 赤陶换成 iOS 的中性冷灰 + 系统蓝。系统蓝取深一档（浅色 `#0062CC`，对卡面 5.6；iOS 的 `#007AFF` 只有 4.0，不够小字用），深色取 `#4DA3FF`（6.3）。一个颜色管所有强调，所以 `--os-accent` 和 `--os-accent-2` 现在同值——两个名字留着，各自单列一条对比度规则，将来再分开时不会有一条悄悄失守。`--os-sage` 同理，名字已经名不副实。

主按钮是实心蓝胶囊，次级按钮是纯文字的蓝（iOS 的 plain 样式），普通按钮是玻璃胶囊。玻璃胶囊那圈边只给页头、左栏底部、卡片工具条和课表卡里的按钮，不放在基础按钮规则上：第一版放在基础规则上，被几十种自定义按钮（任务行、课块、色标行）继承，深色下课程列表每一行都套上了一个框。

`--os-muted` 在填充（`--os-fill`）上不够：统计瓦片的说明文字在「浅色 + 纯黑壁纸」下量到 4.47，闸门拦了下来。压在填充上的小字改走 `--os-body`。

### 铺满：一个控件一种样子

7.0 之前同一件事有好几种长相，这一版每样只留一种：

| 东西 | 只留这一种 |
| --- | --- |
| 分段 / 筛选 | 填充的槽 + 浮起的白胶囊（`.os-segments` `.os-sections` `.os-mobile-switch` `.os-modes` 同一套） |
| 卡里的块 | 填充底 `--os-fill`、`--os-r-inner`、无描边（课程卡、每日小结、统计瓦片、学习目标） |
| 行分隔 | `.5px` 的 `--os-glass-shade`；`--os-line` 只给「卡片边界」那一级 |
| 勾选框 | 圆的 |
| 弹窗 | `shared/components.css`：玻璃弹层、填充输入框、胶囊按钮 |

弹窗皮肤只碰没有类名的按钮和 `.mod-cta`，外加工作台自己的 `.os-button` 系列。带类名的按钮是插件有意设计过的，通用规则压上去会把它们全变成一个样。

### 6.5–6.8

暖燕麦底、纯白卡加一条细描边、复古墨绿作第二色、高反差衬线数字、圆角收紧一档（卡片 14px → 10px，按钮 8px → 6px，导航 8px）。

元数据药丸统一成 20px 高、11px 字、无描边的淡底标签，靠底色分三组：是什么、什么属性、有什么问题。描边是那一排最吵的东西，去掉之后它们才排得成一行印刷品。7.0 起药丸改成胶囊，三组底色换成蓝、琥珀、红。

6.0 没有重做视觉——重做视觉属于新功能，而 6.0 是一次可发布性迭代；6.5 才做了这件事。

## 未决：标注色的三套值

同一个命名颜色在三处用三个值：

| 命名 | 高亮线 | 文字标签 | 调色按钮 |
| --- | --- | --- | --- |
| blue | `#3974a6` | `#3974a6` | `#78bdec` |
| purple | `#8d6bc0` | `#7653a6` | `#b49add` |
| coral | `#e46f61` | `#b84a45` | `#ee8a7c` |

各有各的道理：PDF 上的高亮线要够深才看得见，卡片上的文字要更深才够对比度，按钮要更浅才不抢眼。但 blue 的文字和高亮同值、purple 却不同值，说明这不是有意设计的三层，是分三次写出来的。

6.0 只把它们收成命名令牌，**一个值都没改**。三套值是否真该存在、要不要按明度算法从一个基色派生，留给 6.1 决定。在那之前，改任何一个都只改 `shared/tokens.css`。
