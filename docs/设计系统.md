# 设计系统

> 活文档。`shared/tokens.css` 是唯一定义处，`tools/build.js` 构建时把它内联到每个插件 `styles.css` 的最前面；插件样式只消费 `var(--os-*)`。

这次是真的唯一。6.0 之前 `design/00-tokens.css` 也写着「唯一真相源，禁止再写具体色值」，但它被零个文件引用，副本躺在 `.obsidian/snippets/` 而 `appearance.json` 的 `enabledCssSnippets` 是空的——从未启用。声明唯一没有用，得有机制。现在的机制是构建内联加 `tools/check.js` 的色值提示。

## 对比度闸门

`tools/contrast.js` 对两套主题逐条校验 20 项关系，不达标直接构建失败。这类判断眼睛不可靠——起草 6.1 方案时，我两次凭截图判断颜色都判错了（深色主按钮、任务标题），像素采样才给出正确答案。

| 关系 | 下限 | 挡住的是 |
| --- | --- | --- |
| ~~卡片 / 页面底~~ | ~~1.25~~ | 6.5 并进上面那条二选一 |
| 次级面 / 页面底 | 1.12 | 6.0 时是 1.09 |
| 分隔线 / 卡片 | 1.80 | 6.0 时是 1.43，而所有分区都靠这条线 |
| 正文、次要文字、强调色、危险色对各自底色 | 4.50 | 次要文字铺在 soft 卡片上曾是 4.18，低于 AA |
| 第二强调色 / 卡片 | 4.50 | 6.5 新增。它既当字也当按钮底，两个用途量的是同一对关系 |
| 卡片可辨（面 **或** 线） | 1.25 / 1.80 | 二选一。6.0 是两条都不够，才该被拦 |

6.1 只动明度、不动色相：页面底 `#f4eee5 → #e8e1d7`，次级面 `#eee4d7 → #dcd4c6`，分隔线 `#ded2c3 → #c6b9a8`，次要文字 `#7d685b → #6a5749`。文字的颜色一直是对的，塌掉的是面与面之间的明度差。

## 6.5 换色：纸白 + 深绿

6.1 只动明度、不动色相，因为当时塌掉的是面与面的明度差。6.5 动的是色相：整套暖纸底偏黄，而层级一直只靠「更淡」表达，淡到一定程度就只剩浑浊。

| | 6.4 | 6.5 |
| --- | --- | --- |
| 卡片 | `#fffaf3` 奶油 | `#FFFFFF` 纯白 |
| 页面底 | `#e8e1d7` | `#F8F6F1` 暖燕麦 |
| 次级面 | `#dcd4c6`（交互卡的底） | `#EAE6DC`（只剩悬浮态） |
| 分隔线 | `#c6b9a8` 暖棕 | `#C9C0AA` 一条线管所有 |
| 正文 | `#3d3029` | `#25201D` 暖焦糖黑 |
| 次要文字 | `#6a5749` 浑暖灰 | `#2D4739` 复古墨绿 |

三个判断值得记下来：

**次级面改成比页面底亮。** 闸门要的是「`--os-bg` 和 `--os-soft` 分得开」，没规定方向。旧值比页面底暗，于是「今日要务」那张卡是全页最黄的一块——它是交互卡，却长得像一块底。改成往白走，1.16 照样过闸，而卡片全体归白。

**层级从明度换成色相。** 旧的次要文字 `#6a5749` 和正文只差明度、不差性质，所以「次要」只能靠更淡表达。换成一个不同色相的深绿之后，明度可以留得很深——它对白卡 9.73，比旧值还高，却明显不是正文。

**赤陶红收窄到两处**：左上角的 L，和专注卡里那一个「开始专注」。其余原本用强调色的地方（主按钮、状态标签、高优先、分段选中态、今日要务标记）全部走新增的 `--os-accent-2`。一页里只有一个地方是红的，那个地方才叫重点。

### 闸门拦了两次，第二次它自己的措辞是错的

**第一次**：方案给的页面底是 `#F7F3EA` 配纯白卡，量出来 **1.11**——正好是 6.0 那个数。解法是保住色相与饱和度、只压明度，得到当时的 `#EDE4D0`。

**第二次**：下一轮细则说「提亮净化底层」，给了 `#F8F6F1`；同时把卡片描边定成 `#E6E2D8`。量出来面差 1.08、描边 1.29——两样都撑不住，卡片和底之间什么都没有。

但这一次暴露的是**规则本身写窄了**。原规则写的是「面与面要有明度差」，而真实要求是「卡片要能被认出来」——白卡配一条看得清的描边同样成立，那是另一种正当做法。所以这条改成二选一：

```js
{ any: [{ a: "--os-paper", b: "--os-bg", min: 1.25 },
        { a: "--os-line",  b: "--os-paper", min: 1.8 }], ... }
```

放宽之后 6.0 那次欠账仍然拦得住——它是面 1.11 **且** 线 1.43，两条都不够。测试里把这一点钉死了：不只断言「不合格」，还断言两条候选各自的实测值，否则将来有人把其中一条下限调到 0，那个测试照样绿。

于是页面底可以真的用 `#F8F6F1`，代价是描边从 `#E6E2D8` 压到 `#C9C0AA`（1.81）——仍然是 1px 的细线，但不再是隐形的。分区总得有人扛。

顺带一个反直觉的量化结果：`#EDE4D0` 和 `#F8F6F1` 的**明度只差 8 个点**（87.3% vs 95.9%），饱和度差 12 个点（45% vs 33%）。「发闷」来自饱和度，不是来自暗。

深色那套同理：`#171A17` 的墨绿底配 `#2A2E29` 的卡，1.27；次要文字用浅鼠尾草绿 `#A9BBA5`。两套是同一个判断的两个方向，不是两套独立配色。

## 6.6 液态玻璃

面板改成半透明白底加 `backdrop-filter: blur(20px) saturate(140%)`。四条边不是一个颜色——上缘和左缘受光（`rgba(255,255,255,.85)`），下缘和右缘背光（`rgba(130,115,95,.12)`）——这一条比模糊本身更决定它像不像一块有厚度的玻璃：模糊只让背后糊掉，是那圈方向性的高光让它有了朝向。

### 磨砂需要背后有东西

`backdrop-filter: blur()` 模糊的是面板**背后**的东西。整页底原来是一块平色，模糊一块平色还是同一块平色——整套玻璃写下去，屏幕上一点变化都没有。

页面底有两道极淡的径向渐变（左上鼠尾草、右上暖赤陶），还可以由挂件插件接入 Windows 聚焦壁纸。渐变是没有壁纸时的材质输入；有壁纸时，模糊和饱和度折射才真正明显。改配色时如果把渐变和壁纸一起去掉，玻璃会安静地退化成半透明白块，而且不会有任何报错。

6.8 起玻璃不只用于工作台大面板：专注卡、课程与审计子卡、知识详情、输入字段、六个模块的产品弹窗、PDF 学习侧栏和浮动工具条都消费同一组令牌。层级分为 `--os-glass-strong`（弹窗与学习侧栏）、`--os-glass`（主面板）、`--os-glass-soft`（内层卡）、`--os-glass-field`（输入字段）和 `--os-glass-hover`（悬浮态），不能再用 `--os-bg`、`--os-paper` 或 Obsidian 的 `--background-primary` 临时补一块实底。

番茄钟是例外中的加强版：它面积最大，而且每秒更新，普通玻璃的均匀半透明底会在大面积上重新读成白色实心卡。它因此单独使用 `--os-focus-glass`、`--os-focus-sheen` 与 `--os-focus-blur`，让左上受光、右下暖色折射和背景位移都能直接看见；这些令牌仍分别提供浅色与深色值。

### 玻璃令牌不进闸门

`--os-glass` 那几个是 rgba，`tools/contrast.js` 只认字面十六进制，所以它们量不了。文字实际压在什么底上由 `--os-paper` 记录：那是标准玻璃经过页面遮罩后叠在页面底上的近似等效色（当前为 `#FDFCFA`）。

**两者必须同步改。** 只改 `--os-glass` 不改 `--os-paper`，闸门量的就是一块界面上并不存在的颜色——它会继续报「全部达标」，而那个结论跟屏幕上的东西没有关系。

### 表盘尺寸跟高度走

专注台的进度环第一版按容器**宽度**定尺寸（`min(62cqw, 232px)`），在真实窗口里把大漆按钮挤出了卡片下沿。夹具一条都没响——面板体自带 `overflow-y:auto`，内容超了它就安静地滚，溢出断言量不到。

改成跟容器高度走。上限 200px 是量出来的：面板体 394px，模式条 / 绑定条 / 珠子 / 按钮组占掉 192px。凡是「一列固定元素加一个可伸缩元素」的卡片，那个可伸缩的都该按高度定，不按宽度。

## 令牌

定义在 `:root` 与 `body.theme-dark` 上。自定义属性会继承，所以六个插件都能用，单独启用其中一个也在。

| 组 | 令牌 |
| --- | --- |
| 底色 | `--os-bg` `--os-paper` `--os-soft` `--os-rail` |
| 线与焦点 | `--os-line` `--os-focus` |
| 文字 | `--os-ink` `--os-muted` |
| 强调 | `--os-accent`（赤陶，只剩 L 与开始专注） `--os-accent-hover` `--os-accent-2`（深绿，其余一切强调） `--os-danger` |
| 字阶 | `--fs-display` `--fs-title` `--fs-body` `--fs-meta` `--fs-timer` `--os-serif` |
| 学习热力 | `--os-heat-0` … `--os-heat-4` |
| 标注色 | `--os-mark-{yellow,coral,mint,blue,purple}` 及 `-text` / `-chip` 变体 |
| 元数据药丸 | `--os-pill-{green,warm,alert}-bg` / `-ink` |
| 玻璃材质 | `--os-glass-strong` `--os-glass` `--os-glass-soft` `--os-glass-field` `--os-glass-hover` `--os-glass-rail` `--os-glass-blur` |
| 专注玻璃 | `--os-focus-glass` `--os-focus-sheen` `--os-focus-blur` |

6.5 加了一个 `--os-serif`：展示用的高反差衬线（Bodoni / Didot 一路，取不到退回 Georgia）。Georgia 是为屏幕可读性设计的低反差字，笔画粗细几乎一致，放到 98px 的计时器上就显得敦实；高反差衬线在大字号下才有那股印刷味。用它的只有三处数字——专注计时、左栏时钟、页头气温——因为那是同一种东西的三个尺寸。

字阶只有四级加一个计时器专用展示号。5.4.0 之前散落 22 种字号，差 1px 的相邻值到处都是——密度上去了但层次没建立。工作台在 `@container` 查询里按尺寸重定义这几个字号，改的是 `.os-root`，只影响工作台视图内部，不回头影响别的插件。

## 风格

6.5 起：暖燕麦底、纯白卡加一条细描边、复古墨绿作第二色、高反差衬线数字、圆角收紧一档（卡片 14px → 10px，按钮 8px → 6px，导航 8px）。

元数据药丸统一成 20px 高、11px 字、无描边、4px 等距的淡底标签，靠底色分三组：绿（是什么）、暖棕（什么属性）、淡红（有什么问题）。描边是那一排最吵的东西，去掉之后它们才排得成一行印刷品。

6.0 没有重做视觉——重做视觉属于新功能，而 6.0 是一次可发布性迭代；6.5 才做了这件事。

## 未决：标注色的三套值

同一个命名颜色在三处用三个值：

| 命名 | 高亮线 | 文字标签 | 调色按钮 |
| --- | --- | --- | --- |
| blue | `#3974a6` | `#3974a6` | `#78bdec` |
| purple | `#8d6bc0` | `#7653a6` | `#b49add` |
| coral | `#e46f61` | `#b84a45` | `#ee8a7c` |

各有各的道理：PDF 上的高亮线要够深才看得见，卡片上的文字要更深才够对比度，按钮要更浅才不抢眼。但 blue 的文字和高亮同值、purple 却不同值，说明这不是有意设计的三层，是分三次写出来的。

6.0 只把它们收成命名令牌，**一个值都没改**。三套值是否真该存在、要不要按明度算法从一个基色派生，留给 6.1 决定。在那之前，改任何一个都只改 `shared/tokens.css`。
