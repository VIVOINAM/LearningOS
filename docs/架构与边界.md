# 架构与边界

> 活文档：改了实现就改这里。不写版本号——版本在 `version.json`，改了什么在 `CHANGELOG.md`。

## 六个模块

Learning OS 是一个产品，拆成六个 Obsidian 插件只是加载形态。它们一起构建、一起部署、互相调 API，锁步同一个版本号。

| Owner | 公开接口 | 持久化位置 |
| --- | --- | --- |
| codex-capture | listTasks、taskStats、updateTask、patchTask、captureNote/Task/Project、create/read/patch/rename/deleteProject | 原 Markdown；索引只在内存 |
| codex-focus | dispatch、state、sessions、settings、setSettings、markLogged | 自身 data.json |
| codex-study | engine.attachFile/overview/select、openTextbook、findCard、revealCard | 自身 data.json + 教材笔记 |
| codex-recall | list、add、addCard、has、rate、remove、review | 自身 data.json |
| codex-widgets | renderRail(host, {slot})、`--os-wallpaper`（挂在 body 上的 CSS 变量） | 自身 data.json |
| codex-workbench | activate、open、courseCatalog、configureCourse、openVersionLog | 自身偏好 data.json + 课程笔记/日记 |

`tools/plugins.js` 是这份清单的机器可读版，顺序即加载依赖顺序：owner 先加载，工作台最后绑定它们。`--plugin` 可把验证、构建和部署限定到单个插件。

### 挂件的边界

挂件插件对外还有第二个接口，形式是一个 CSS 变量而不是方法：它把今天那张 Windows 聚焦图挂成 body 上的 `--os-wallpaper`，工作台的样式表消费它。用变量而不是回调，是因为挂件插件不该知道 `.os-root` 长什么样，而工作台不该知道那张图是从哪来的。变量不存在时那一层是 `none`，背景自动退化，样式里不需要分支。

7.0 起这个接口有两个声明，同进同出：`--os-wallpaper` 给出图，`body.os-wallpaper-on` 这个类给出「背后现在是一张照片」。玻璃的亮度钳位挂在后者上——钳位是为照片准备的，没有照片时它反而会把暖燕麦底拖成灰（第一版无条件开，页头天气卡变成了一个灰方块）。

为什么是类而不是又一个变量：CSS 里没法按「某个变量存不存在」开关一组声明，而钳位要开关的是两个令牌。类是能做这件事的最小手段，而且它和变量一样只是 body 上的一个声明——挂件仍然不知道 `.os-root` 长什么样。


`codex-widgets` 只对外给一个 `renderRail(host, {slot})`，返回 `{destroy(), paint()}`。挂件能去三个地方：`top`（左栏导航上方）、`bottom`（左栏导航下方）、`header`（今日页标题那一行的右端，横排）。工作台提供这三块地方，哪个挂件去哪一块由用户在挂件设置里定，工作台不参与这个判断。它不 import 工作台，也不读任何其他插件的数据——倒计日是自己填的列表，不从任务的 `due` 或课程的考试日期取。这条界限是故意的：左栏挂件是装饰性的，不该因为 codex-capture 停用而空掉半块。

工作台那边只负责给三块 `div` 和一个生命周期（`mountWidgets` / `onClose` 里 `destroy`），拿到 `undefined` 时把容器置 `hidden`，左栏回到 6.3 的样子。

页头那块建在 `.os-header-actions` **里面**，不是它旁边：actions 的 `flex-basis` 是 46%，按钮靠右端排，挂件搁在外面就会被那个空盒子推到页头正中间孤零零悬着。

`hidden` 只表示「插件不在」。挂件区**空不空**是渲染结果，会随设置变，而设置改动只走 codex-widgets 自己的 `repaint()`，工作台不会被通知——所以那件事交给 CSS：挂件区空时带 `data-empty`，样式表按它收起来。最初写成工作台在 `mountWidgets` 里判断有没有卡片，结果在设置里把时间挪下去之后，品牌和导航之间留下一道只有间距的空缝，要等下一次 `refresh()` 才消失。

走秒由挂件插件自己的一个 interval 驱动、喂所有挂载点；节点脱离文档后挂载点在下一拍自我销毁，工作台反复 `refresh()` 不会攒下一串还在跑的计时器。

曾经有第七个插件 codex-iteration，负责把版本说明写进 `00 工作台/版本迭代.md`。6.0 起版本日志是构建产物，它没有剩下的职责，已删除；入口成为工作台命令「打开版本迭代」。

## 数据契约

### 课表是一篇笔记，不是一份数据

工作台的课表页和今日页「今天的课」读的是库里 frontmatter 带 `type: timetable` 的笔记，一学期一篇。插件不存副本：笔记是给人读、给人改的，调课了在 Obsidian 里改一行表格就算数；插件再存一份，两份一定会漂，漂了之后没人知道该信哪一份。

表格格式就是契约，解析在 `codex-workbench/timetable-model.js`（纯函数，带测试，并且测试直接解析仓库里那篇真的课表笔记）：

| 表 | 怎么认 | 取什么 |
| --- | --- | --- |
| 上课时段 | 表头同时有「星期」「时间」「课程」「教室」 | 每行一个每周重复的时段；「课程」格里 `[[路径\|别名]]` 的路径带六位课程代码 |
| 教室位置 | 表头有「教室」「地址」 | 教室 → 地址（`街道 · 楼栋`）、楼层；一格可写多个教室，用顿号分开 |
| 课程与教师 | 表头有「代码」「教师」 | 课程代码 → 教师、官方名称 |

「时间冲突」那张表也有星期、时间、课程三列，靠没有「教室」列和上课表分开——第一版没加这一条，冲突表的五行被当成了五节课。

结束日期格里写了「⚠」或「待核实」的时段，原值留在 `officialTo`，实际按本学期其他时段最晚的结束日截断。解析不了的行不丢，进 `skipped`，课表页会说出来。

多篇课表时，`plugin.timetable()` 选今天落在其学期内的那篇；都不在，取最近一个还没开始的；再没有，取最后结束的那篇。解析结果按路径加修改时间缓存在插件上。

### 课堂笔记

路径、模板、任务规格和公式转换都在 `codex-workbench/class-notes.js`（纯函数，带测试）。路径本身就是契约：`课堂笔记/<代码> <课名>/<YYYY-MM-DD> <课名>.md`，`parseNotePath` 靠它认出「这是哪门课哪一天」，粘贴处理只在认得出的笔记里接管。

「总结笔记」任务走 codex-capture 的 `createTask` 写进今日任务，工作台不另存一份。去重靠任务的 `tags` 里 `课堂笔记/<日期>/<代码>` 这个标签，而不是工作台记一个「今天建过了」——记在工作台里，换台设备、重装插件就会再建一遍；标签跟着任务行走，删除的墓碑行里也还在，所以删掉的不会复活。排序时 `courseIdFor` 从这个标签读出课程代码，接上课程紧迫度。

图片不改全库的附件设置（那会让所有笔记的附件换地方），而是在 `editor-paste` / `editor-drop` 里只接管课堂笔记。

### 复习的调度键

`codex-recall` 的调度单元有两种，键的形状决定是哪种（见 `codex-recall/core/keys.js`）：

| 键 | 是什么 |
| --- | --- |
| `03 知识库/笔记.md` | 整篇笔记 |
| `book/数学分析.pdf#k3x9-ab12` | 那本书里的一张卡片 |

6.2 之前只有前者，于是 codex-study 产出的卡片没有任何路径进入复习队列——在整个 codex-study 里 grep `recall` 返回零结果，捕获系统和复习系统互不相识。现在 study 的卡片菜单通过 `getPlugin('codex-recall')` 调 `addCard`，recall 反过来通过 `getPlugin('codex-study')` 调 `findCard` 取内容、`revealCard` 跳回原页。两边都是动态获取，任一插件停用时对应入口不出现，不留按下去没反应的按钮。

调用方用 `key` 去 review / remove / rate，用 `path` 去判断文件还在不在——卡片条目两者不同。`'#'` 只有在后缀长得像 study 生成的 id 时才当分隔符，所以「读书笔记#3.md」不会被误判。

事件：`codex-focus:before-change`（学习时长结算）、`codex-focus:changed`、`codex-focus:finished`、`codex-capture:changed`、`codex-recall:changed`。

- 任务、计时、复习的更改各自串行化；写盘失败拒绝操作并报告错误，不留半截状态。
- 复习与计时转换有回滚保护。
- UI 不卸载其他插件拥有的服务。
- 工作台通过 `getPlugin` 动态获取 owner；timer / sessions 代理只读，写入一律走专注 owner 的 API。
- 停用某个 owner 后相关操作停用或显示提示。禁止在工作台内置第二套计时 / 任务 / PDF 状态——两套状态一定会漂移。

## 构建与产物

- 运行入口是每个插件的 `main.js`；`tools/bundler.js` 把目录内的相对 require 内联成自包含产物，`require("obsidian")` 留给运行时。
- `shared/` 只在构建时内联，不作为独立模块部署。样式有两份共用层，按顺序内联到每个插件 `styles.css` 最前面：`tokens.css`（令牌）和 `components.css`（弹窗皮肤）。每个插件都带一份是故意的——模块可以单独启用，只启用 codex-capture 时它的弹窗也得长得对。
- 产物 manifest 的 `version` 由 `tools/build.js` 从 `version.json` 注入。**源码 manifest 不带 version**，带了 `tools/check.js` 会直接失败——不是校验一致，是不许写，因为能写就会漂。
- 部署白名单只有 `main.js`、`manifest.json`、`styles.css`，不含 `data.json`。
- `dist/plugins/` 是暂存产物（`--stage`），不进 git；`.obsidian/plugins/` 是真正加载的那一份。

## 校验闸门

`tools/check.js` 的硬失败项，每一条都对应一次真实的欠账：

| 规则 | 挡住的是 |
| --- | --- |
| 源码 manifest 带 `version` | 六个版本号各自漂移（曾经 study 5.6.5 而 recall 1.0.0） |
| `CHANGELOG.md` 缺 `version.json` 当前版本的小节 | 版本日志静默少一节 |
| 日志里的模块名不在 `tools/modules.js` 清单里 | 写错模块名，条目分不回插件 |
| 插件目录下还有自己的 `CHANGELOG.md` | 六份日志互相漂移 |
| 活文档里写死了某个版本号 | 三处文档各写一个版本、没一处说对 |
| 产物里有相对 require 或源码目录路径 | 产物不自包含 |

`tools/legibility.cjs` 是第四道，跟着 `smoke-visual.cjs` 跑：把真正挂载的界面摆在八种最坏背景上，在文字锚点处采样实测对比度，低于 4.5 失败。它量的是渲染结果，不是令牌——前三道都看不见 rgba 和运行时状态，而壁纸和那个「图片可见度」滑块两样都是。
