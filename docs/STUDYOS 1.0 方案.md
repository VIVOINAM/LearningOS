# STUDYOS 1.0 方案

> 方案文档。执行完毕后按 6.1 的先例移入 `07 归档/插件版本文档/`，该留下的判断补进 [架构与边界](架构与边界.md)。
> 本轮不是美学迭代，是一次改名——而改名要有内容，否则只是版本号通胀。
> 所以照 7.0 的规矩先量。量出来的结论是一句话：**这个产品叫 Learning OS，界面的主语却是任务。**

## 一句话

7.0 把今日的视觉语言铺满其余八页，动的是构图。1.0 换的是主语：**让「在学的材料」成为一等对象**。

名字从 Learning 改成 Study，只有在材料真的成为系统里的一个东西之后才成立。现在它不是。

## 先量，再改

三组数都取自这台机器上正在跑的数据——`03 知识库/教材切片/学习元数据.json`、`.obsidian/plugins/l-os-focus/data.json`、`.obsidian/plugins/l-os-recall/`。不是抽样，是全部。

### 一、材料这一侧有多空

| 量 | 数 |
| --- | --- |
| 库里的 PDF | 759（`book/` 14，`课程文件/` 745） |
| 有阅读记录的 | 183 |
| **翻过第 1 页的** | **2** |
| 有任何标注的 | 1 |
| 标注总数 | 38（26 高亮 / 11 切片 / 1 疑问） |
| **间隔复习队列里的卡** | **0** |

最后一行不是「暂时为空」。`l-os-recall` 靠 `saveData` 落盘，而 `.obsidian/plugins/l-os-recall/data.json` 这个文件**不存在**——它从未被写过一次。这个插件跑到今天，一张卡都没进过队列。

而 6.2 专门修过这条通路：study 的卡片菜单通过 `getPlugin('l-os-recall')` 调 `addCard`，recall 反过来调 `findCard` 取内容。通路是通的，38 条标注一条都没走过去。

7.0 量到间隔复习页 78% 空、教材页 79% 空、待解疑问页 79% 空。那三个数不是排版的结果，是这张表的结果——**把空页排得更好看，页还是空的。**

### 二、专注这一侧在学什么

52 段 focus，743 分钟，34 段跑完。按 `task` 字段分组，前几名：

| 段数 | `task` |
| --- | --- |
| 19 | `阅读：book/卷1·走向抽象的结构主义：代数与空间.pdf` |
| 8 | `阅读：卷1·走向抽象的结构主义：代数与空间` |
| 6 | `完成obsidian工作台最后收官` |
| 5 | `学习数学 📅 2026-09-17` |
| 3 | `自由专注` |
| 1 | `阅读：课程文件/大学教材中文/普通化学原理（第二版）.pdf` |

合计 **29 段、326 分钟——占全部专注时间的 44%，绑的是一份材料，不是一个任务。**

这不是谁自己想出来的写法，是 `reading-flow.js:12` 生成的：打开 PDF 就 dispatch 一段 `阅读：${file.basename||file.path}`。**产品其实已经在把专注绑到材料上了**，只是那个绑定的载体是一串给人看的文案。

### 三、那串文案对不上

`阅读：` 后面跟的是 `file.basename||file.path`——有 basename 就用 basename。

而 `study-engine.js:51` 取一本书的历史时长时，按 `s.task === '阅读：' + path` 精确匹配，用的是**完整路径**。

两处拼的不是同一个字符串。上面那张表里 19 段路径形、8 段 basename 形，指着同一本书，正好是这件事留下的化石。

这条的影响面被 `endedAt < startedAt` 限住了，只波及迁移点之前的历史段，所以它不是一个在冒烟的 bug。但它是**根因的标本**：材料和时间之间的关系，现在靠两处代码各自格式化同一个字符串来维持。

## 根因：材料在这套系统里没有身份

任务有 id，专注段有 id（`1788616404530-3g8koze1`），复习单元有 key——`l-os-recall/core/keys.js` 甚至为它专门写了两种形状，一种指整篇笔记、一种指书里的一张卡。

材料只有一个路径。路径当 key 本身没问题，recall 就是这么用的。问题是**它跨 owner 的时候被格式化成了展示文案**，于是：

- focus 里存下来的是 `阅读：卷1·走向抽象的结构主义：代数与空间`，不是那本书；
- 三种写法（`阅读`、`阅读：<basename>`、`阅读：<path>`）指着同一本书，聚合不了；
- 一本书「我在它上面花了多久」要靠字符串反推；
- 一条标注变成一张复习卡，要人手动走一次菜单——38 条里走了 0 条。

**「材料」是这个产品新名字里的那个词，却是系统里唯一一个没有身份的东西。**

## 改名这件事

### 能改什么，不能改什么

**不能改 `manifest.json` 的 `id`。** 六个 id 是 Obsidian 认插件的依据，也是 `.obsidian/plugins/<id>/data.json` 的路径——改了等于全部数据失联，74 段专注、183 条阅读记录、课程配置一起丢。`tools/plugins.js`、部署白名单、仓库目录名全部跟 id 走，一并不动。

**要改的是人看得见的那一层**：manifest 的 `name` / `description`、README、四篇活文档、CHANGELOG 顶部标题、`00 工作台/使用说明.md`、`版本迭代.md` 的生成模板，以及左上角那个 L。

CHANGELOG 里 6.0 之前的历史条目保持原样、不追认——那条规矩已经写在文件抬头，改名同样适用。

### 版本号：这一条要先定

`tools/release.js` 不校验版本号单调递增（第 95 行只校验 CHANGELOG 顶部那节与目标一致），所以 7.0 之后发 1.0 机械上能过。

但这个仓库的回退点靠 tag。`v7.0.0` 之后出现 `v1.0.0`，「哪个更新」从此只能靠人记——而这份文档抬头那句「一篇文档要么永远正确，要么永远不再改」，管的就是这类靠人记的事。

**建议：名字重置，号不重置。** 产品叫 StudyOS，`version.json` 继续往 8.0 走，CHANGELOG 换标题不换序列。若坚持叫 1.0，就要接受 tag 排序永久错乱，并在[发布流程](发布流程.md)里写明这次断点是什么、怎么读。

这一条请先定，它决定下面几节落地时的写法。

## 五件事

顺序有依赖，1 是地基，4 必须排在 2 之后。

**一、材料成为一等对象。**

`l-os-study` 对外给出材料的身份：`materialId` 仍然就是路径，但由 study 一处产出，别处不再自己拼。`l-os-focus` 的 session 增加 `material` 字段，与 `task` **并列**，而不是挤进 `task`。`reading-flow.js` dispatch 时两个都给：`task` 给人看，`material` 给机器用。`study-engine.totals()` 改按 `material` 聚合，字符串匹配那条降级成迁移期的兼容路径并标注截止版本。

这一条动了数据契约（focus 的 session 形状、study 的公开接口），要同步改[架构与边界](架构与边界.md)那张表，并给 focus 的 `schemaVersion` 升一档。**本轮唯一一次动契约，也是最难回退的一处**——开工前那节说的就是它。

**二、标注到复习卡，要有一条不用想起来的路。**

38 → 0 说明「有一个菜单项可以加卡」等于没有。改成：**切片和疑问两类标注默认进队列**，高亮不进——26 条高亮涌进去只会把队列淹掉，而高亮本来就是「先划下来」的意思，不是「要背下来」。用户可以在那条标注上取消。

这是本轮唯一一处改默认行为的地方，CHANGELOG 要写清原来是什么、为什么改。

**三、三个空分段合成「在学的材料」一页。**

教材、待解疑问、间隔复习不是三件事，是同一件事的三面：手上这本书、它留下的问题、它欠的复习。合成一页之后，7.0 第七件事里最难的三条空态**直接消失**——不是给空页设计空态，是取消这三个空页。

`LEAF_LABELS` 从十项变八项；三个旧 tab id 保留为别名，命令、链接、`setTab` 调用照旧可用。这是 6.3 收导航时用过的做法，照抄即可。

**四、学习单元与任务同席进今日。**

`rankTodayTasks` 现在只排任务，而且 `console-model.js:349` 明确写了那是刻意的：「今日页仍然只放任务行，界面上一个新元素都不加，变的只是顺序」。1.0 推翻这条——到期的复习卡、「继续读第 66 页」，应该和任务一起被排。

推翻一条写过理由的判断，CHANGELOG 里要写明当时为什么那么定、现在为什么不同：**6.2 那时队列里是 0 条，排进去等于排了个空。** 第二件事让它不再是 0，前提才变了。所以这一条必须排在二之后，顺序不能换。

**五、专注面板显示「在学什么」。**

有了一和四，表盘下面那行才有东西可写：不是「第 3 段 / 共 4 段」，是「卷1 · 第 66 页 · 今天 42 分钟」。纯展示，放最后。

## 闸门

七件事是这一轮的结果，闸门决定它下一轮会不会漂回去。1.0 加两道。

**闸门五：跨 owner 的关联不许是展示文案。**

`check.js` 加一条：源码里不许把中文前缀拼进 `task:` 或任何用于匹配的键（`'阅读：' + x` 这一类模板串）。白名单给纯展示用途，但**同一个串不得既展示又匹配**。这条挡的正是第三张表里那 19 比 8。

**闸门六：主路径冒烟。**

现有九个 smoke 覆盖计时、复习、阅读、序列化，但没有一个跑完整条链：打开教材 → 划一条切片 → 进复习队列 → 到期出现在今日。加 `smoke-study-loop.js` 跑完它。

38 条标注 0 张卡这件事，任何一道现有闸门都看不见，**因为每一跳单独看都是好的**。断的是跳与跳之间，而那里没有测试。

## 不做什么

- **不做美学。** 7.0 正在做，1.0 不碰构图、配色、玻璃、令牌。两件事搅在一起，出问题时分不清是谁。
- **不改 manifest id、目录名、部署路径。** 理由见上。
- **不动任务系统。** l-os-capture 的接口一个不碰。本轮是把学习那半边补齐，不是把任务那半边削掉。
- **不做移动端与平板。** 和 7.0 同一条，留给后面。
- **不清理 `.obsidian/plugins/l-os-study/data.json`。** 它是首次迁移留下的旧副本，`l-os-study/README.md` 写明「不删除」。它比权威库旧（第 48 页 vs 第 66 页），看起来像两套状态在漂移，其实是化石。别顺手删。

## 开工前

**7.0 必须先发出去。** 理由和 7.0 方案里「先把 6.4 到 6.8 发出去」一模一样：这个仓库不开 feature 分支，回退点靠 tag。1.0 第一件事就动 focus 的 session 形状——所有改动里最难回退的一类，必须有一个干净的锚点在前面。

**另外，7.0 自己还欠一笔。** `shared/tokens.css` 的改动现在在工作区里未提交，而它的注释写着「钳位的具体数值……是 `tools/legibility.cjs` 在七种对抗背景上量出来的——改这里必须重跑它」。`tools/` 里没有这个文件。

也就是说 `contrast(.38) brightness(1.22)` 这组数目前没有任何东西背书，而那句注释让它读起来像有。这正是这个仓库反复说的那句「声明没有用，得有机制」——只是这次反过来了：**机制被声明成已经存在了。** 补上它，或者把那句注释改成实话。留着不管不行。
