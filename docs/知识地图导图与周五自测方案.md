# 知识地图导图与周五自测方案

> 方案文档，2026-09-26 定稿。**进度（同日）**：阶段 1–5 已实现并部署，阶段 6 的文档已更新（[知识模块联动](知识模块联动.md)、使用说明、CHANGELOG）；待实机验收（公式渲染、平板手写笔拖动与点按、完整做一门）后归档。执行完毕后按先例移入 `07 归档/插件版本文档/`，该留下的判断补进 [知识模块联动](知识模块联动.md) 与 [设计系统](设计系统.md)。版本号在发布时定。
> 本轮范围由五个决定框定：**知识地图由 agent 总结维护，用户只查看**、**掌握度四档保留，由周五自测填写**、**每周五全考、每门 10 题、选择题为主**、**自测是左栏与知识地图平级的一项**、**新增左右平衡的思维导图模式**。

## 一句话

知识地图从「课堂笔记标题目录」改成一份 agent 维护的**课程概念图谱**，用两种方式看：导图看全貌、列表看细节；每周五在插件里做一套 agent 出的选择题，插件本地判分，把结果写成每个概念的掌握度。一学期下来，导图从一张灰色骨架长成一张长满、大部分是绿色的图。

## 为什么改

7.4 的知识地图（见 [知识模块联动](知识模块联动.md)）是按日期分组的课堂笔记标题树，实际用下来有四个问题：

1. **掌握度看不出来**：四档自评在树里只剩一个小圆圈，一眼看不出哪里薄弱；而且全靠手点，没人点，就全是「待自评」。
2. **关系看不出来**：「连接知识点」能记先修 / 相关，但地图上画不出来；前置关系「只由用户明确添加」，而用户不会去手连。
3. **只有时间顺序**：看得出哪天讲了什么，看不出这门课的概念是怎么搭起来的。
4. **详情重复**：右侧灰框把左边树上的小节又列了一遍。

还有两处底层问题，决定了不能只改界面：

- **概念 ID 跟标题文字走**：`learning-hub-model.js:35` 的 `nodeKey` 是「课程代码 + 小写标题」，标题一改 ID 就变，挂在上面的掌握度、关系、学习成果都会脱钩。
- **状态存在插件 `data.json`**：`learning-hub-store.js:5` 把掌握度和关系写进 `plugin.data.knowledgeMap`；Obsidian 运行时会覆盖这个文件，agent 从外面写进去会被冲掉。

## 市面方案取舍

| 形态 | 代表 | 取 / 舍 |
| --- | --- | --- |
| 掌握度方格 | Khan Academy 课程掌握度、ALEKS | **取**：四档与 Khan 的四级一一对应；化成节点底色和课程卡色带 |
| 机器生成的导图 | NotebookLM 思维导图、Xmind AI | **取**：agent 生成，人只展开和点选；点节点出解释 |
| 先修关系图 | Math Academy | **取一半**：关系由 agent 生成，只在选中概念时画出，不做常驻的关系网 |
| 力导向网络图 | Obsidian 关系图谱、Logseq | **舍**：连线稀疏时是一团散沙，也没有阅读顺序 |
| 自由白板 | Heptabase、Canvas | **舍**：要人摆位置 |
| 矩形树图 / 旭日图 | — | **舍**：小块里放不下中文标题 |

## 总体结构

```
agent 写（库里的文件）                          插件读 / 写
────────────────────────                        ────────────────────────
03 知识库/知识地图/<代码 课程>.json   ──读──▶   知识地图：导图 / 列表
03 知识库/周五自测/<周>.json           ──读──▶   周五自测：作答、判分
                                                 │
03 知识库/知识地图/掌握度.json         ◀──写──   自测结果 + 手动修正
```

- **三份文件，谁写谁的**：图谱和题库只由 agent 写；掌握度记录只由插件写（agent 只读）。互不覆盖，也不再往 `data.json` 里放知识数据。
- **插件完全离线**：判分、换算、渲染都在本地，不调用任何 AI。agent 只在两个时刻出场：课后整理图谱、周五出题。
- **课堂笔记本身不动**：agent 只读笔记，写图谱；笔记的写作规则仍按 `L-OS专属/AGENTS.md`。

## 一、概念图谱（数据）

### 1. 文件与格式

每门课一份：`03 知识库/知识地图/057274 静力学与结构力学.json`。

```json
{
  "course": "057274",
  "title": "静力学与结构力学",
  "updatedAt": "2026-09-26T20:00:00+02:00",
  "skeletonSource": "课程文件/057274 静力学与结构力学/01 课件/Introduzione al corso.pdf",
  "notes": [
    { "path": "03 知识库/我的课程/2026-27/课堂笔记/057274 静力学与结构力学/2026-09-22 静力学与结构力学.md",
      "integratedAt": "2026-09-26T20:00:00+02:00" }
  ],
  "chapters": [
    { "id": "ch01", "order": 1, "title": "质点静力学", "status": "learned" },
    { "id": "ch05", "order": 5, "title": "桁架", "status": "planned" }
  ],
  "concepts": [
    {
      "id": "c-force-equivalence",
      "chapter": "ch02",
      "title": "力系等效与简化",
      "firstTaught": "2026-09-23",
      "summary": "两个力系对刚体的合力与对任一点的合力矩都相同，则二者等效。",
      "formulas": ["\\vec R=\\sum_i \\vec F_i", "\\vec M_O=\\sum_i \\vec r_i\\times\\vec F_i"],
      "points": ["力偶只产生转动效应，可在刚体内任意平移", "…"],
      "prereqs": ["c-moment"],
      "related": ["c-distributed-load"],
      "sources": [{ "path": "…/2026-09-23 静力学与结构力学.md", "heading": "力系等效与单力简化" }],
      "examples": [{ "path": "…/2026-09-24 静力学与结构力学.md", "heading": "例 3", "title": "…" }],
      "legacyKeys": ["057274:%E5%8A%9B%E7%B3%BB%E7%AD%89%E6%95%88%E4%B8%8E%E5%8D%95%E5%8A%9B%E7%AE%80%E5%8C%96"],
      "retired": false
    }
  ],
  "ignored": [{ "path": "…", "heading": "一页速查", "reason": "学习指引" }]
}
```

字段说明：

- **`chapters`**：整门课的章节骨架。`planned` 是还没讲到的章，学期初就铺好；讲到了改成 `learned`。
- **`concepts`**：概念是「能单独出题考」的单位。静力学现在拆出 47 个知识点，整理后预计十几到二十个概念，原来的三四级小节变成概念的 `points`。
- **`points`**：概念下的要点，导图第四层。agent 每次整理可以补充，知识库的「厚度」体现在这里。
- **`legacyKeys`**：这个概念对应的旧 `nodeKey`，用于迁移（见下文）。
- **`notes`**：已整理进图谱的课堂笔记，插件据此判断哪篇还没整理。
- **`ignored`**：明确跳过的小节（学习指引、骨架标题等），用于覆盖检查。

### 2. 维护规则（agent 必须遵守）

写成独立规范 `08 插件开发/docs/知识图谱与出题规范.md`，并在 `L-OS专属/AGENTS.md` 加一行指向它，保证不同 agent 按同一套规矩写。要点：

- **ID 固定**：一个 ID 只指一个概念，永不复用。改名保留原 ID；合并或删除时标 `retired: true`，不直接删，历史测验记录才挂得上。
- **有出处**：每个概念至少一处 `sources`；`formulas` 必须能在来源原文里找到，不许自己编。
- **不遗漏**：沿用 7.4 已验证的标题规则（学习指引整块跳过、例题挂到所在概念、标题去编号日期页码），每个课堂笔记小节要么归进某个概念，要么列进 `ignored`。
- **先修不成环**。
- **只增量更新**：只处理 `notes` 里没有、或修改时间晚于 `integratedAt` 的笔记。
- **分章依据**：优先课程大纲（如 `Introduzione al corso.pdf`）或关联教材目录；都没有就按讲授顺序，只铺已学部分。
- **例题**：挂到它考察的概念下，不单独成概念。

### 3. 校验脚本

新增 `tools/check-knowledge-graph.cjs`，每次 agent 更新后运行，也并入 `npm test`：

- JSON 结构与必填字段；概念 ID、章节 ID 唯一。
- 所有 `sources`、`examples` 指向的文件和标题存在。
- `prereqs`、`related` 指向存在且未退役的概念；先修图无环。
- **覆盖检查**：用 7.4 现有的 `topicsFromNote` 解析同一批课堂笔记，每个解析出的主题都必须落进某个概念的 `sources` / `legacyKeys`，或出现在 `ignored` 里。旧解析器从「地图本身」退为「检查 agent 有没有漏」。
- 公式抽查：`formulas` 里的每条，去空白后能在来源小节的原文中找到。

### 4. 迁移

- 插件首次读到某门课的图谱时，把 `data.json` 里 `knowledgeMap.statuses` 中能按 `legacyKeys` 对上的档位写进掌握度记录，标为「迁移」；对不上的列进提示，不静默丢弃。
- `knowledgeMap.relations` 交给 agent 一次性并入图谱的 `prereqs` / `related`。
- 学习成果笔记 frontmatter 里的 `concepts` 存的是旧键：插件读取时经 `legacyKeys` 映射到新 ID，**不改写**这些笔记文件。
- 迁移完成后 `data.json` 里的旧数据保留一个版本，下个版本再清。

### 5. 过渡期

还没有图谱文件的课，继续用 7.4 的标题解析显示，不会空白；导图模式对这些课不可用，切换按钮置灰并说明原因。

## 二、知识地图：界面

### 1. 课程总览（入口）

保留 7.4 的样子：只给有课堂笔记的课画卡，卡底一条掌握度色带，其余的课并成一行字。新增一种提示：有课堂笔记还没整理进图谱时，卡上写「9/24 笔记未整理」。它是待办提醒，整理完就消失，不是常驻计数。

### 2. 课程页

顶部：`← 全部课程`、`[导图 | 列表]` 切换、`[全部 | 需巩固 | 本周新学]` 筛选、`这门课的学习成果`。

- 首次进入默认**导图**；之后记住上次的选择（按课程记）。
- 筛选对两种模式都生效：导图里不符合的节点变淡，不删除，保持全貌。
- 「本周新学」指 `firstTaught` 在本周一到周日之间。

### 3. 导图模式（左右平衡）

```
                      ┌ 力是向量 ●                         ┌ 力矩与力偶 ○
      ① 质点静力学 ───┼ 力的合成 ●      ② 刚体静力学 ──────┼ 力系等效与简化 ◐ ─┬ 力偶可平移
           ╲          └ 直角坐标分解 ◐       ╱             └ 分布荷载 ○        ├ 等效条件
            ╲                              ╱                                    └ 例题 · 5
             ────── 静力学与结构力学 ─────
            ╱                              ╲
      ④ ┄ 梁 ┄（未学）              ③ ┄ 桁架 ┄（未学）
```

**布局**

- 课程居中，章节分到左右两侧。按每章展开后的叶子数累计分配，使两侧高度接近。
- 阅读顺序为顺时针：右侧从上到下，左侧从下到上。章节节点带序号 ①②③，顺序不用猜。
- 层级：课程 → 章 → 概念 → 要点 / 公式 / 例题。第四层默认收起，点开概念才长出来。
- 默认只展开 `learned` 的章节；`planned` 的章收成一个灰色虚线节点。展开 / 收起状态按课程记住。
- 布局用自写的整洁树算法（子树高度累加、父节点居中），不引第三方库。插件开发目录目前没有任何第三方依赖，markmap / jsMind 会带进 d3，不划算。

**节点**

- 节点是普通 HTML 按钮，绝对定位；连线是底层一张 SVG，用三次贝塞尔曲线。
- 概念节点底色表示掌握度，同时用形状区分，不只靠颜色：

  | 档位 | 形状 | 颜色倾向 |
  | --- | --- | --- |
  | 待自评 | 空心圆 | 中性灰 |
  | 需巩固 | 带叹号 | 暖色 |
  | 已理解 | 半实心 | 浅绿 |
  | 能应用 | 实心 | 绿 |
  | 未学 | 灰色虚线框 | — |

- 本周新长出的节点带一个小「新」字标记，下周自动去掉。
- 节点一律实底，保证压在液态玻璃和壁纸上仍然认得出字；对比度进 `tools/legibility.cjs` 检查，深浅色并列。
- 先修关系平时不画。选中概念时，用虚线弧高亮它的先修（指向它）和后续（从它出发），其余节点变淡。

**操作**

- 拖动平移；Ctrl + 滚轮或双指缩放（Obsidian 里触控板捏合就是 Ctrl + 滚轮）；普通滚轮平移。
- 右上角「适应窗口」一键看全图。
- 画布设 `touch-action: none`，否则平板上手写笔降级成触控后拖不动。
- 键盘：方向键在相邻节点间移动，Enter 打开概念卡，`+` / `-` 缩放，`0` 适应窗口。
- 系统要求减少动效时，展开、收起、平移不做动画。

**点选**

点概念节点，从右侧滑出概念卡，内容与列表模式的右栏完全相同；导图留在左边可以继续点。Esc 或再点空白处收起。

### 4. 列表模式（章 → 概念两层）

```
第1章 质点静力学              │ 第2章 ›
  ● 力是向量                  │ 力系等效与简化          9/23 讲
  ● 力的合成                  │ [待自评|需巩固|已理解|能应用]
  ◐ 直角坐标分解              │ 依据：9/25 自测 第3题 ✗ 第7题 ✓
第2章 刚体静力学              │ 一句话：……
  ○ 力矩与力偶                │ 关键公式：……
  ◐ 力系等效与简化  ←         │ 要点：……
  ○ 分布荷载                  │ 先修：力矩与力偶 · 后续：分布荷载
┄ 第3章 桁架（未学）          │ 例题 · 5
                              │ ▸ 课堂笔记原文（折叠）
```

- 左栏按章分组，最多两层，不再按日期分组；日期挪到概念卡里。
- 「例题（9/23）」「例题逐题解析（9/24）」这类节点删掉，例题挂到概念下。
- 行尾的例题数字去掉，放进概念卡。
- 圆点加大，形状与导图一致。

### 5. 概念卡（两种模式共用），从上到下

1. 章节面包屑 `第2章 ›`、标题、「9/23 讲」。
2. 四档按钮，下面一行依据：最近一次自测的题号与对错，或「9/26 手动」。
3. 一句话（`summary`）。
4. 关键公式（`formulas`，MathJax 渲染）。
5. 要点（`points`）。
6. 先修 / 后续 / 相关：可点的概念标签，点了跳过去（导图里同时平移到该节点）。
7. 例题列表，点击跳到课堂笔记对应位置。
8. 课堂笔记原文：沿用 7.4 的就地渲染，**默认折叠**。
9. 其他课堂来源、记忆线索：保留。
10. 操作只留「打开课堂笔记」。

删掉的：「连接知识点」按钮与 `RelationModal`（关系交给 agent）；7.4 灰框里重复列小节的那块。「提炼记忆笔记」按钮从概念卡移除，学习成果页工具栏上的保留（见「本轮不做」）。

## 三、周五自测

### 1. 节奏

| 时间 | agent | 用户 |
| --- | --- | --- |
| 周一到周四，每次课后 | 读当天新增的课堂笔记，增量更新概念图谱 | 不用做 |
| 周五，用户总结完本周后 | 按用户指令出本周题库，跑校验 | 让 agent 出题 |
| 周五 | — | 在「周五自测」里作答 |
| 作答完 | — | 插件判分，写回掌握度；想看就打开知识地图 |

一周只有周一到周四有课，周五正好总结和自测。出题由用户手动触发，不走定时任务。

### 2. 出题规则（写进同一份规范）

- **范围**：本周有课堂笔记的每门课都考，某门课那周没课就不考。目前是静力学、化工过程计算、电工学、流体力学 4 门，40 题，约 40 到 60 分钟。
- **每门 10 题**，约 6 道概念题 + 4 道应用题。
- **每个被考概念至少 2 题**，所以一周每门约测 5 到 7 个概念。
- **抽样优先级**：本周新学的核心概念 → 仍是「需巩固」的 → 按间隔复查的「已理解」。没考到的维持原档位，覆盖靠跨周累积。
- **题型**：单选为主，另有多选、判断、数值填空（带允许误差）。不出简答和推导，它们需要 AI 批改，破坏离线。
- **干扰项**：用典型错误构造（漏力偶矩、符号取反、单位错），不用明显荒谬的选项。
- **防错**：每题附解析和原文出处；计算题由 agent 用脚本实算后再出选项；风格参考 `课程文件/<课>/03 真题`。
- **配图**：只引用课堂笔记里已有的附件（`![[…]]`），不让 agent 自己画受力图。

### 3. 题库格式

`03 知识库/周五自测/2026-W39.json`（ISO 周）：

```json
{
  "week": "2026-W39",
  "createdAt": "2026-09-25T18:00:00+02:00",
  "courses": [
    {
      "course": "057274",
      "questions": [
        {
          "id": "q01",
          "concepts": ["c-force-equivalence"],
          "level": "concept",
          "type": "single",
          "stem": "下列哪组力系与单个力 $\\vec F$ 等效？",
          "options": ["…", "…", "…", "…"],
          "answer": [2],
          "explanation": "…",
          "source": { "path": "…", "heading": "力系等效与单力简化" }
        }
      ]
    }
  ]
}
```

- `level` 取 `concept` 或 `application`，决定换算规则。
- `type`：`single` / `multiple` / `truefalse` / `numeric`（数值题用 `answer: {"value": 12.5, "tolerance": 0.05}`）。
- 校验脚本 `tools/check-quiz.cjs`：每门 10 题；答案在选项范围内；概念 ID 存在于图谱且未退役；每个被考概念至少 2 题；`source` 存在；公式定界符成对。不合格的题库插件拒绝加载，并说明哪一题不合格。

### 4. 左栏「周五自测」

- 模块表（`console-view.js:24`）新增一项，与「知识地图」平级。
- 入口页：本周题库按课程分组，每门显示作答进度和「开始 / 继续 / 查看结果」。没有本周题库时显示一句「本周还没有出题」，不加角标、不加倒计时。
- 作答：一题一屏，题干和选项用 `renderMarkdown` 渲染公式；选项顺序由插件打乱，避开 agent 的位置偏好；按钮加大，方便平板手写笔点按。
- 每题固定有「不确定」选项，选它按没掌握算，不去赌那 25%。
- 每题可点「这题有问题」，标记后不计分，并记进作答文件，下次出题时 agent 读取并避开。
- 每答一题立即保存，中途关掉下次接着做。
- 答完一门出这门的结果：每题对错、解析、原文链接，以及每个概念的档位变化（例：力系等效与简化 待自评 → 已理解）。

### 5. 作答与掌握度

作答文件 `03 知识库/周五自测/2026-W39 作答.json`，每题记选择、用时、有问题标记、是否为首次作答。

**重做**：允许重做练习，但只有第一次作答计入掌握度。

**换算规则**（按周、按概念，只看未被标记有问题的首次作答）：

| 作答情况 | 判定 |
| --- | --- |
| 有概念题答错，或选了「不确定」 | 需巩固 |
| 概念题全对，应用题有错或没考应用题 | 已理解 |
| 概念题和应用题都对 | 能应用 |
| 本周没考到 | 维持原档位 |

**掌握度记录** `03 知识库/知识地图/掌握度.json`：只追加，不覆盖。每条记概念 ID、档位、来源（自测 / 手动 / 迁移）、时间、依据题号。地图显示最新一条；手动修改和自测结果冲突时，以时间最新的为准，两条都留着。

## 四、分阶段执行

每个阶段结束都跑 `npm test`；涉及插件源码的阶段先 `node tools/build.js --stage` 再 deploy，同步后提示在 Obsidian 命令面板重载。

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| **1. 图谱数据** | 写 `知识图谱与出题规范.md`（图谱部分）；`check-knowledge-graph.cjs`；让 agent 读大纲铺骨架，并整理静力学 9/22 到 9/24 三篇笔记 | 校验通过；**用户审**概念粒度、分章、摘要、先修关系 |

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| agent 给错标准答案，把用户误判成「需巩固」 | 解析 + 出处；计算题脚本实算；「这题有问题」不计分；阶段 4 先审题 |
| 四选一蒙对，证据弱 | 每概念至少 2 题；「不确定」选项；干扰项用典型错误 |
| 每周覆盖不全 | 抽样优先级 + 跨周累积；没考到维持原档位 |
| agent 整理漏了小节 | 覆盖检查用旧解析器兜底，漏一个就校验失败 |
| agent 改名换 ID，历史脱钩 | ID 固定规则 + `retired` + 校验脚本比对上一版 ID 是否消失 |
| 图谱落后于笔记 | 课程卡「未整理」提示；过渡期回退 |
| 导图在大课上太挤 | 未学章节收起、第四层默认收起、筛选变淡、适应窗口 |
| 壁纸下看不清 | 节点实底；`legibility.cjs` 检查深浅两套 |
| 题库里有答案，文件列表能直接看到 | 自测场景可接受；需要时再做简单编码，本轮不做 |

## 本轮不做

- 学习成果模块的改造：保持 7.4 原样；是否改成 agent 生成，另议。
- 导出 Obsidian Canvas。
- 简答 / 推导题与 AI 批改。
