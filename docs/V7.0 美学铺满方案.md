# V7.0 美学铺满方案

> 方案文档。执行完毕后按 6.1 的先例移入 `07 归档/插件版本文档/`，该留下的判断补进 [设计系统](设计系统.md)。
> 本轮范围由四个决定框定：**主线是把今日的语言铺满其余八页**、**深色与浅色并列一等**、**只覆盖桌面宽屏**、
> **任何背景下字都要认得出**——最后一条是看到实拍截图后加的，它排在其余三条前面。

## 一句话

6.5 到 6.8 这四轮美学全部发生在「今日」一页。7.0 把那套语言铺完，并且让它在两个地方同样成立：深色主题，以及**任意一张壁纸之上**。

后一条是 6.7 挂上聚焦壁纸时欠下的账——那次给界面换了一个不受控的底，而整套配色是按一个固定的底设计的。

## 四条根因

### 一、rgba 字面量绕过了全部机制

`l-os-workbench/styles.css` 五万字里，未收进令牌的十六进制色值只剩 **2 处**——令牌纪律是真的有效。但 `rgba(` 有 **8 处**，其中三处写死了只属于浅色的值：

```
.os-modes .os-mode.is-active { background: rgba(255,255,255,.58) }
.os-dial-arc                 { stroke:     rgba(46,74,59,.8)    }
.os-read-fill                { background: rgba(46,74,59,.8)    }
```

上面量出来的三条不达标，正好就是这三行。

两道闸门对 rgba 都是睁眼瞎：`check.js` 的色值规则只匹配 `#[0-9a-fA-F]{6}`，而且只 `console.warn`，不是硬失败；`contrast.js` 的 `themes()` 同样只收 `#` 开头的六位值——设计系统文档里那句「玻璃令牌不进闸门，因为只认字面十六进制」记的是玻璃，但漏掉的**不止是玻璃**，是所有 rgba。

这不是谁忘了。这是 6.0 之前那个老问题的同一个形状：**能写就会写**。`design/00-tokens.css` 自称唯一真相源却被零个文件引用，靠的是声明；现在令牌真的唯一了，靠的是构建内联加闸门。rgba 这条路上还没有机制，所以它漂了。

### 二、美学只发生在今日

玻璃面板、方向性描边、衬线数字、凹陷分段控件、进度环、元数据药丸——六样东西全部只在今日页有。其余八页停在 6.0 的构图。逐页清单在下一节。

这条本身不是 bug，是节奏问题：6.5 到 6.8 每一轮都拿今日当试验田是对的，但试验成功之后没有铺。再做一轮只改今日的美学，只会把落差拉得更大。

### 三、页面级构图没有规范，于是长出了五种

同一件事——「这一页的主要动作放哪」——现在有五种答案：

1. 今日：页头右端（`.os-header-actions` 里）
2. 行动清单 / 笔记库 / 间隔复习 / 每日小结：浮在卡片右上角，和卡里的搜索框对不上
3. 大项目：卡片内部一排纯文字链接
4. 课程：每张子卡自己带三个按钮
5. 学习热力：四个统计数直接浮在页面底上，不在任何卡里

### 四、余量为零，而且可读性是一个能滑到 0 的设置

两件事叠在一起，缺一个都不至于这么糟。

**其一，令牌是按「刚好达到 4.5」设计的。** `--os-muted` 对 `--os-paper` 就是 4.5，闸门给的下限也是 4.5——余量为零。底色只要浮动一点它就掉下去。上面那张表里过与不过的分界线正好就是余量：`--os-ink` 对白卡 13 以上，所以它扛得住一整片蓝天；`--os-muted` 只有 4.5，所以它遇到什么塌什么。

固定的底上，4.5 是一个合格的目标。不受控的底上，4.5 是一个必然失守的目标。

**其二，可读性被做成了一个用户能滑到零的设置项。** `l-os-widgets/core/widgets.js` 里 `wallpaperVisibility = clamp(value, 0, 100, 14)`，`main.js` 换算成 `--os-scrim-opacity = 1 - visibility / 100`。默认 14% 对应遮罩 0.86；滑到 100% 时遮罩是 **0**，一层都不剩。

6.7 的 changelog 写过：「这个不透明度是刻意选的……调低会好看，但闸门会开始量一个比实际情况乐观的值。」那句判断是对的，但它只写进了文档，没有写进代码——滑块照样能滑到底。又一次「声明没有用，得有机制」。

而且这件事对两道闸门都不可见：它是运行时状态，不是令牌。

## 压倒一切的一条：任何背景下都要认得出字

这一条排在七件事前面，因为它决定其余七件的做法。

**保证不可能靠选颜色得到。** 背景是一张每天换的照片，是不受控输入；任何「这个灰对那个白是 4.5」的推导，在照片进来的一刻就失效了。只能靠四层结构，加一道闸门。

**层一：遮罩拆成两层——用户能调的是画面感，不是可读性。**

- **画面层**（可调 0–100%，就是现在那个滑块）：只作用在面板之外的页面底，也就是留白、水槽、页边。照片在这里可以完全清晰。实拍截图里湖水和岩壁在页边是成立的、甚至是好看的，坏掉的全是压着字的地方——所以这一层不该被削。
- **托底层**（不可调）：面板底下，以及页面级文字所在的那条带。浓度由闸门定，滑块滑不动它。

这条拆分本身就是答案：照片要的和文字要的不是同一块地方，现在它们共用一个滑块，所以只能二选一。

**层二：把模糊打开——这件事 `tokens.css` 自己预告过。**

`--os-glass-blur` 现在是 `none`，6.6.1 为性能关的，注释写着：「将来页面底换成有细节的东西（图片、噪点、真实内容穿透），模糊就重新有意义了，那时改这一个令牌即可。」壁纸 6.7 就到了，没人把这个令牌翻回来。预告兑现了，动作没跟上。

但**光有模糊不够：一片亮天空模糊之后仍然是一片亮天空**。模糊只降低细节的高频成分，不改变平均亮度，而对比度输在平均亮度上。所以要配一个钳位——`backdrop-filter: blur() saturate() brightness() contrast()`，把任意背景压进一条已知窄带，再叠底色。钳不钳得住可以算，也可以量。

**层三：页面级文字要有自己的底。**

页标题、副标题、页头元信息现在没有任何面。给页头那条带一道自上而下的渐变托底——不是加一个盒子（那会让「阅读界面优先做减法」失守），是一道看不出边界的暗化。2.15 和 2.94 两处一起解决。

**层四：次要文字要有余量。**

`--os-muted` 从「刚好 4.5」提到「对自己的面 7.0 以上」。代价是压缩它和 `--os-ink` 的明度差，也就是压缩层级——6.5 遇到过同一个矛盾，当时的解法是**让层级由色相承担、不由明度承担**，于是明度可以留得很深。同一个解法这次还能用，只是不能再用那个会让整页小字发绿的绿。

这四层里，一和三是结构，二和四是取值。结构不做，取值怎么调都是在跟照片赌。

## 七件事

顺序有依赖：1 和 2 是地基，做完之后 3 到 7 才好落。

**1. 面板高度跟内容走。** `.os-panel` 不再撑满可用高度；需要占满的（今日的双栏、每日小结的九宫）显式声明。顺带解决 6.6 那条「表盘尺寸跟高度走」留下的隐患——凡是「一列固定元素加一个可伸缩元素」才按高度定，其余按内容定。

**2. 一套列表行。** 行动清单、笔记库、教材、待解疑问、间隔复习、大项目现在各写各的。收成一个组件：两行结构（标题 + 药丸行，6.1 已经在今日验证过）、正文有最大行宽、行内动作跟在内容右侧而不是贴在面板最右缘。教材页那个「阅读」隔着 1150px 的问题在这里消失。

**3. 一套工具条。** 页面级动作一律去页头右端，跟今日一致；卡片右上角不再浮东西。破坏性动作（删除项目）不与普通动作同排同级。

**4. 元数据药丸铺开。** 课程卡那行跑字改成药丸；三组底色的分法（绿=是什么、暖棕=什么属性、淡红=有什么问题）已经在令牌里，只是没人用。

**5. 分段控件收成一个。** 现在有两套：今日的 `.os-modes`（凹槽 + 浮起的选中块）和其余页的 `.os-segments`（`--os-soft` 底 + 描边）。留前者。

**6. 深色补齐。** 三条不达标的 rgba 提成令牌并给深色分支。这一条不是单独修三行——是把「深色是浅色的降级版」这个默认改掉：每条视觉决定两套主题同时定、同时量。

**7. 空态。** 间隔复习、教材、待解疑问、今日要务、笔记库右栏——现在要么是一行灰字浮在大白框中央，要么什么都没有。空态是这些页面的常态，按常态设计。

## 另外三件：时间、天气、动态图标

这三件都落在 `l-os-widgets`，和铺满九页正交，但都压在「任何背景下认得出字」那条上，所以顺序不能随便排。

### 八、时间改 24 小时制，并且只剩这一种

先说一件**不用等 7.0** 的：24 小时制已经是代码默认——`clockText(date, { hour12 = false })`，而 `normalize` 里写的是 `hour12: clock.hour12 === true`，缺省就是 false。这台机器的 `.obsidian/plugins/l-os-widgets/data.json` 里 `clock.hour12` 是 `true`，是设置开着。在挂件设置里关掉，立刻就是 `13:19:44`。

7.0 要做的是把这个开关**拿掉**。理由不是「少一个选项」，是排版：

时钟用 `--os-serif` 那支高反差衬线展示号。十二小时制不补零，于是 `9:59` 跳到 `10:00` 的那一刻读数宽了一位——196px 的固定左栏里、27px 的大字，那是肉眼可见的抖动。这个仓库已经吃过一次同类的亏，`clockText` 上面那段注释记着：6.4 把「上午 」拼进读数前面，大字折成两行、卡片从 62px 长到 99px，挂件区冒出一条滚动条。**时段和补零是同一个问题的两面**——都是让一个限定语去和读数抢固定宽度里的位置。

`meridiem()` 跟着删，它只为十二小时制存在。

### 九、天气更醒目——但它必须排在托底层后面

这一条的顺序是死的，不是偏好。

页头那行天气实测 6.72，过关。但前面记过，那是**撞上的**——采样那块照片正好是深色岩壁。换一张亮天空的图，同一个元素就是 2 点几。现在把它放大加重，做出来的是一个更大的、更看不清的气温。

所以：先落「压倒一切的一条」里的**层三**（页头那条渐变托底带），天气再变醒目。反过来做等于把问题放大。

醒目本身不用换字——气温已经在用 `--os-serif`，是设计系统里记的「同一种东西的三个尺寸」之一（专注计时、左栏时钟、页头气温）。要动的是配重：温度当主，天气文字和地名退成次要，图标和温度取同一视觉重量，整组从页头的附属信息升成一个独立的读数块。

### 十、动态图标：三条硬约束，先写下来再画

1. **必须内联。** 部署白名单只有 `main.js`、`manifest.json`、`styles.css` 三个文件（见[架构与边界](架构与边界.md)），所以图标不能是 SVG / Lottie / GIF 资源文件——只能是 JS 里构建的内联 SVG，或者纯 CSS 画的形。这条直接定了动画的复杂度上限：能做「云飘、雨落、日轮转、闪电跳」，做不了逐帧序列。`WMO_ICON` 现在是 10 个码组，也就是要画 10 个状态。

2. **只走 transform / opacity。** 6.6.1 那一轮查了四个闪烁来源，结论是关掉 `backdrop-filter`、把每秒无条件写 `textContent` 改成「没变就不写」。一个一直在跑的图标如果引起重排或重绘，那笔账当场回来——而 7.0 还打算把模糊重新打开（层二），那时背景过滤的代价比 6.6 更高。所以：动画用 CSS 驱动，不要挂到 `MOUNT_TICK` 上（那个 interval 喂所有挂载点，往里加活最贵）；视图不可见时停；`prefers-reduced-motion` 时停。

3. **过期的数据不许动。** `weatherStale()` 已经在判缓存过没过期（默认 60 分钟）。缓存过期、取数失败、没填坐标这三种情况下，图标要降级成静态。**用动效表达一个其实没更新的读数，就是用展示效果编数据**——[协作规则](../../06%20L-OS/协作规则.md)第四条挡的正是这件事。一个还在下雨的图标配一个三小时前的温度，比不画动画糟。

另外，现在的图标是 Obsidian 内置 lucide 名（`sun` / `cloud-rain` / …）走 `setIcon`，拿不到 `setIcon` 时整段跳过、不留空位。换成自绘之后这条退路没了，要自己留一条：画不出来退回 lucide，再不行只留温度文字。

## 闸门：四条新机制

这一节比上面那些更重要。七件事是这一次的结果，闸门决定它下一次会不会再漂回去。

**闸门一：rgba 字面量升为硬失败。** `check.js` 的色值检查扩到 `rgba(` / `rgb(`，并从 `console.warn` 提成 `failed = true`。白名单只给纯黑纯白的阴影与高光（`rgba(0,0,0,α)` / `rgba(255,255,255,α)` 出现在 `box-shadow` 里），因为那两个在两套主题下都成立。有色相的 rgba 一律必须是令牌。

**闸门二：`contrast.js` 学会 alpha 合成。** 现在它只认六位十六进制，于是玻璃、凹槽、药丸——界面上真正压着文字的那些底——一条都量不到，只能靠 `--os-paper` 那个「手算的等效色」代打，而设计系统文档自己写着「两者必须同步改，不然闸门量的是一块界面上并不存在的颜色」。**需要人记得同步的机制不是机制。** 让 `themes()` 支持 `rgba(...)`，按声明的 backdrop 合成出实际色，规则表里直接写 `{ a: "--os-mode-active-ink", b: "--os-mode-active-bg", over: "--os-focus-glass" }`。上面那三条 1.12 / 1.68 / 2.16 就是它该拦下的第一批。

**闸门三：夹具量构图，不只量「有没有坏」。** 现在 `layout-results.json` 里每页记的是 `broken`、`bodyOverflow`——全是「有没有崩」。加两条构图断言：面板尾部空白占比不得超过阈值；同一页里主要动作的落点不得出现两种以上模式。这一条最容易写成摆设，所以阈值要按实测定（今日 0%、每日小结 1%、课程 2% 是已经成立的档位），而不是拍一个宽松到谁都能过的数。

**闸门四：对抗性背景。** 前三条管的是令牌和构图，管不到「一张没见过的照片」。夹具把整套界面渲染在一组最坏背景上——纯白、纯黑、高饱和红、高饱和蓝，再加三张真实聚焦图（含实拍那张）——在固定的文字锚点上采样实测对比度，任何一处低于 4.5 构建失败。

锚点表跟着界面走：新加的文字要么进锚点表，要么明确标注成装饰。上面那 14 行就是这道闸门的手工版，7 处不过；把它自动化，就是把「在任何背景下都认得出字」从一句愿望变成一条会红的断言。

顺带，这道闸门也覆盖那个滑块：托底层的浓度要能在滑块拉到 100% 时仍然过关，否则拆两层就白拆了。

## 不做什么

- **不换配色。** 6.5 那次换色的判断（层级从明度换成色相、赤陶收窄到两处）成立，没有推翻的理由。7.0 动的是构图和一致性。
- **不做移动端与平板。** 按本轮定的范围，只覆盖桌面宽屏。窄屏现在确实是塌的（左栏文字折行、任务行四个纯文字操作平铺），单独记一笔，留给下一轮。
- **不做动效——除了天气图标那一处。** 页面转场、列表进出、状态切换的微交互都不做：`--os-glass-blur` 现在是 `none`，是 6.6.1 为性能关掉的，而层二还要把它重新打开；动效那条路要先还完那笔账。天气图标是例外，约束见第十件。
- **不动功能——例外都在 `l-os-widgets` 里，共三处。** 六个 owner 的公开接口、数据契约一个不碰。三处例外：遮罩拆两层（滑块语义从「图片可见度」变成「页边图片可见度」，托底层不再跟它走）、`clock.hour12` 开关删除、天气从页头附属信息升成独立读数块。三处都是用户可见的行为改动，CHANGELOG 里要写清楚原来是什么、为什么改。
